# Tampere Keikat - Gig Calendar & Discovery Platform

A high-performance, static web application for discovering and filtering live music gigs in Tampere. Built with vanilla JavaScript for maximum speed and reliability, featuring a dynamic calendar, real-time filtering, and responsive design.

## 🚀 Features

- **Dynamic Calendar Navigation**: Seamlessly browse gigs by month with visual indicators for active dates.
- **Smart Data Loading**: Bundled data ensures instant load times and eliminates CORS/API errors.
- **Advanced Filtering**: Filter gigs by genre, search by artist/venue, and view specific dates.
- **Responsive Design**: Fully optimized for mobile, tablet, and desktop devices.
- **Zero Dependencies**: Pure HTML, CSS, and JavaScript – no build steps or frameworks required.
- **Offline Capable**: Works even if the external JSON source is unavailable (uses bundled fallback data).
- **Automated Scraping**: Daily updates via GitHub Actions from 11+ local music sources.

## 📂 Project Structure

## 🛠️ Installation & Deployment

This project is designed to be deployed as a **static site** via **GitHub Pages** with automated daily updates.

### Quick Deploy (5 minutes)

1. **Create a new repo on GitHub** (github.com → New repository). Public, no README/license needed.

2. **Upload these files** to the repo:
   - Click "Add file" → "Upload files"
   - Drag in everything from this folder **including** the `.github` folder
   - Commit to the `main` branch

3. **Turn on GitHub Pages**:
   - Repo → Settings → Pages
   - Set Source to **GitHub Actions** (NOT "Deploy from a branch")

4. **Run the workflow manually (first time)**:
   - Go to Actions tab
   - Click "Update Tampere gig data and deploy" workflow
   - Click "Run workflow" → Run on `main` branch
   - Wait for completion (check logs for event counts)

5. Your site will be live at: `https://YOUR_USERNAME.github.io/YOUR_REPO/`

### Local Development

```bash
# Install dependencies (Python 3.8+)
pip install playwright beautifulsoup4 lxml

# Install browser binaries
playwright install

# Run scraper locally
python scrape.py

# View locally
# Open index.html in browser or use Live Server
```

## 🔧 Troubleshooting

### Gigs not showing up / Calendar empty?
**Browser cache issue** - The app updates frequently but browsers cache aggressively.

**Fix:**
1. **Hard Refresh**: `Ctrl + Shift + R` (Windows) or `Cmd + Shift + R` (Mac)
2. **Clear Site Data**: F12 → Application → Storage → "Clear site data"
3. **Incognito Mode**: Try private browsing window

### Scraper returns 0 events?
Check the GitHub Actions log for the `scrape` job:
- Look for "parsed N events" lines
- If N=0, the site's HTML has changed
- Check `source_status` in `data.json` for per-source errors

### "No commits between branches" error?
```bash
git add index.html
git commit --allow-empty -m "Force update: Refresh bundle"
git push origin main
```

### Data not updating after scraper runs?
Ensure `FALLBACK_RAW` in `index.html` is updated. The app prioritizes bundled data for reliability. If you only change `data.json`, the live site might not reflect changes if fetch is bypassed (intentional for stability).

## 📝 Maintenance

### Updating Gigs Manually
You can hand-edit `data.json` directly (array of `[date, time, title, venue, genre, free, url]` rows) and push — no need to wait for the scraper.

### Fixing a Broken Source
1. Check `source_status` in `data.json` or Actions log to identify the broken source
2. Edit the corresponding file in `sources/`:
   - **meteli**: `sources/meteli.py` → `parse_meteli_anchor_text()`
   - **kohokohdat**: `sources/kohokohdat.py` → `parse_month_page()`
   - **puistokonsertit**: `sources/puistokonsertit.py` (most reliable)
   - Genre guessing: `sources/common.py` → `guess_genre()`
3. Test locally with `python scrape.py`
4. Push changes

### Adding a New Source
1. Create `sources/newsite.py` with a `fetch_newsite()` function
2. Import it in `scrape.py`
3. Add one line to the `jobs` dict
4. Each source is self-contained — bugs can't leak between sources

## 🍪 Analytics & Privacy

The site includes a GDPR-compliant cookie consent banner. Analytics is **inactive by default**.

**To enable Google Analytics:**
1. Create GA4 property at [analytics.google.com](https://analytics.google.com)
2. Get Measurement ID (format: `G-ABC1234567`)
3. In `index.html`, find:
   ```js
   const GA_MEASUREMENT_ID = "G-XXXXXXXXXX";
   ```
4. Replace with your ID and push

**How consent works:**
- Banner shows on first visit (Accept/Decline)
- GA script only injected **after** Accept is clicked
- Choice stored in `localStorage` (not cookies)
- "Cookie preferences" link in footer allows changing preference
- If ID is placeholder, Accept logs warning but injects nothing
